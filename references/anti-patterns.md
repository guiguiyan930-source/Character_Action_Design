# 反模式清单（Anti-Patterns）

> ★ v2 新增（P0-4 落地）。这些是实战中踩过的坑——出图出现镜像污染、武器换手、身份漂移的根源，全部沉淀为「禁止写法」+「正确写法」对照。
> 产出动作卡前，逐条核对本清单。

---

## 一、Prompt 写法反模式

### 反模式 1 · 「左右镜像 / 对称复制」触发整体翻转
**错误写法**：
```
"左右镜像姿态，双手对称"
```
**后果**：AI 把整帧水平翻转，不对称特征（红臂、独眼、单侧披甲）被镜像到对侧。
**正确写法**：
```
asymmetry_lock: "右臂深红异化爪套永远在角色右侧，禁止镜像翻转"
prompt: "...right arm mutated red claw gauntlet on the character's right side, never mirrored..."
```

### 反模式 2 · 不声明武器数量与持手
**错误写法**：
```
"手持链镰攻击"
```
**后果**：AI 随机画出两把链镰、或攻击途中换手。
**正确写法**：
```
weapon_hand_lock: "仅右手持一把链镰，数量与持手全程不可变"
prompt: "...holding exactly one scythe-chain in the right hand..."
```

### 反模式 3 · 省略身份锚
**错误写法**：
```
"挥剑动作，16 帧"
```
**后果**：跨帧出现性别/体型/服装漂移（如女性刺客变成有胡须男性）。
**正确写法**：
```
identity_anchor: "暗夜刺客织羽·女性·精瘦·双匕首·正派"
prompt: "<身份锚逐字注入>, slash motion, 16 frames..."
```

### 反模式 4 · 有不对称特征却省略 asymmetry_lock
**错误写法**：角色设定里写了"右臂异化"，但动作卡 prompt 里完全没提。
**后果**：AI 不知道这是不可变的硬特征，部分帧丢失或自行发挥。
**正确写法**：每个动作卡必填 `asymmetry_lock`（无不对称特征写 `none`，但必须有该字段）。

### 反模式 5 · 只写 3 个关键姿势，无帧号映射
**错误写法**：
```
关键姿势：起势 / 命中 / 收势
```
**后果**：3 帧不足以约束 16 帧，中间帧 AI 自由发挥，出现帧间抖动、动作节奏失衡。
**正确写法**：
```
key_poses:
  - frame: 1   height: mid  pose: "..."
  - frame: 4   height: low  pose: "..."
  - frame: 8   height: high pose: "..."   # hit_frame
  - frame: 12  height: mid  pose: "..."
  - frame: 16  height: mid  pose: "..."
```

## 二、设计流程反模式

### 反模式 6 · 不按游戏类型路由，全量 48 动作一把抓
**后果**：战棋角色设计了连招与浮空，塔防单位设计了跳跃，产能浪费且动作冗余。
**正确做法**：先查分类框架第五节「游戏类型 × 动作包」路由表，再叠加预算裁剪。

### 反模式 7 · 动作卡之间无状态机衔接
**后果**：动作清单进不了引擎，动画师仍需手工补取消/打断逻辑。
**正确做法**：战斗动作卡必填 `transitions`（can_cancel_to / interruptible / hit_frame）。

### 反模式 8 · 用主角预设做小怪，用精简档做 Boss
**后果**：小怪动作过度设计，Boss 压迫感不足。
**正确做法**：小怪用预设 2（8 动作最小集），Boss 用预设 3 + N 模块阶段化动作。

### 反模式 9 · 输出前跳过自检
**后果**：镜像、换手、漂移错误流入下游，返工成本高。
**正确做法**：按 SKILL.md 第十节检查清单逐项自检，重点跑「帧循环检查」：16→1 闭环、持手一致、配色漂移 ΔE、剪影对齐。

## 三、检查口诀

> **一锁二数三锚四帧**：
> - 一锁：asymmetry_lock（不对称特征锁）
> - 二数：武器数量 + 持手（weapon_hand_lock）
> - 三锚：身份锚（identity_anchor）逐字注入
> - 四帧：5 帧关键姿势 + 帧号映射（F1/F4/F8/F12/F16）
