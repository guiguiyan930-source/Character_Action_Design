# Character_Action_Design
> 面向游戏 2D/像素/立绘角色的动作设计工作流。输入一份已锁定的角色设定，输出可直接用于「8 方向关键姿势」与「16 帧连续动画」阶段的动作清单、动作描述与 AI 出图 Prompt。

---

## 一、Skill 定位

- **上游**：角色三视图（正/侧/背）已确认，角色的体型、服装、道具、配色已锁定。
- **本 Skill 负责**：根据角色的**职业 / 性格 / 武器 / 世界观**，产出「该角色应有哪些动作 + 每个动作怎么动 + 每个动作的 AI 出图 Prompt」。
- **下游**：
  1. 8 方向关键姿势生成（每个动作 × 8 方向 = 关键帧）
  2. 16 帧连续动画生成（每个方向的关键帧扩展为 16 帧序列）

## 三、输入项（Inputs）

执行本 Skill 前，必须先收集以下信息。缺失项须**先向用户确认**，不要臆测。

| 编号 | 输入项 | 说明 | 是否必填 |
|------|--------|------|----------|
| I1 | 角色三视图 | 正/侧/背视图图片或描述，用作动作 Prompt 的锁定参考 | ✅ 必填 |
| I2 | 角色职业 / 定位 | 例：战士、法师、盗贼、村民 NPC、Boss | ✅ 必填 |
| I3 | 性格 / 气质 | 例：沉稳、活泼、狂躁、优雅 | ✅ 必填 |
| I4 | 武器 / 道具 | 例：单手剑+盾、法杖、双匕首、无武器 | ✅ 必填 |
| I5 | 世界观 / 美术风格 | 例：像素、Q版、写实、赛博朋克、和风 | ✅ 必填 |
| I6 | 用途场景 | 例：横版 ARPG、俯视角 45°、回合制立绘 | ✅ 必填 |
| I7 | 动作复杂度预算 | 需要多少个动作（基础 6 个 / 标准 10 个 / 完整 15+ 个） | ⭕ 可选，默认「标准 10 个」 |
| I8 | 特殊动作需求 | 例：必须包含"骑马"、"施法蓄力"、"处决" | ⭕ 可选 |

## 四、动作分类体系（Action Taxonomy）

所有动作按用途归入 5 大类。设计时**按类挑选**，避免遗漏或堆砌。

### A. 基础状态类（Idle & Locomotion） — 任何角色必备
| 编号 | 动作 | 说明 |
|------|------|------|
| A1 | Idle 待机 | 静止呼吸，体现性格与气质 |
| A2 | Walk 行走 | 常速移动 |
| A3 | Run 奔跑 | 冲刺 / 快速移动 |
| A4 | Turn 转身 | 方向切换过渡（可选） |

### B. 战斗动作类（Combat） — 战斗角色必备
| 编号 | 动作 | 说明 |
|------|------|------|
| B1 | Attack Light 轻攻击 | 快速普攻 |
| B2 | Attack Heavy 重攻击 | 蓄力 / 强攻击 |
| B3 | Skill / Cast 技能施放 | 特殊技，可含蓄力+释放两段 |
| B4 | Block / Parry 格挡 | 防御姿态（可选） |
| B5 | Dodge / Roll 闪避 | 翻滚 / 侧移 |

### C. 受创与死亡类（Damage & Death） — 战斗角色必备
| 编号 | 动作 | 说明 |
|------|------|------|
| C1 | Hurt 受击 | 短暂硬直反馈 |
| C2 | Death 死亡 | 倒地 / 消散 |
| C3 | Revive 复活 | 起身（可选） |

### D. 交互动作类（Interaction） — NPC / 剧情角色必备
| 编号 | 动作 | 说明 |
|------|------|------|
| D1 | Talk 对话 | 手势 + 表情 |
| D2 | Pickup / Use 拾取使用 | 弯腰、举物 |
| D3 | Sit / Sleep 坐 / 睡 | 静态交互 |
| D4 | Emote 情绪表达 | 挥手、鞠躬、鼓掌 |

### E. 特殊动作类（Special） — 按角色定制
| 编号 | 动作 | 说明 |
|------|------|------|
| E1 | Mount / Ride 骑乘 | 有坐骑角色 |
| E2 | Transform 变身 | 有形态切换角色 |
| E3 | Ultimate 大招 / 处决 | Boss 或主角专属 |
| E4 | 剧情专属动作 | 由 I8 指定 |

## 五、动作预算参考（Complexity Budget）

| 预算档位 | 建议动作数 | 动作组合示例 |
|----------|-----------|--------------|
| 精简（NPC / 背景角色） | 4–6 | A1, A2, D1, D4 |
| 标准（普通可玩角色 / 敌人） | 8–10 | A1, A2, A3, B1, B2, B3, C1, C2, D1 |
| 完整（主角 / Boss） | 12–16 | A1–A3, B1–B5, C1–C3, D1, D4, E3 |

## 六、转译规则（Character → Action）

将角色输入转译为动作细节的**四条映射规则**：

1. **职业 → 战斗动作模板**
   - 近战战士：B1 横斩 / B2 上劈 / B3 冲锋斩
   - 法师：B1 弹指法术 / B2 蓄力法阵 / B3 领域大招
   - 盗贼：B1 短刀连刺 / B2 背刺 / B3 烟雾闪避
   - 弓手：B1 快射 / B2 蓄力箭 / B3 多重箭
   - NPC：仅保留 A + D，跳过 B / C

2. **性格 → 动作韵律**
   - 沉稳 → 幅度小、频率低、重心稳（Idle 微呼吸）
   - 活泼 → 幅度大、频率高、有跳跃（Idle 换脚）
   - 狂躁 → 姿态前倾、动作凌厉（Attack 大幅甩动）
   - 优雅 → 弧线运动、末端有停顿（Idle 手部延展）

3. **武器 → 姿态锁定**
   - 单手剑+盾：右手持剑、左手举盾于胸前
   - 双持：双手对称、重心居中
   - 法杖：法杖持于优势手、非优势手辅助
   - 无武器：拳握 / 掌开，按流派定
   - **所有动作 Prompt 都必须显式描述武器状态与手部位置**

4. **世界观 → 视觉风格锁**
   - Prompt 尾部固定追加：`, {美术风格}, {画面比例}, {线稿/上色规格}`
   - 例：`, pixel art 32x32, clean outline, limited palette`

## 七、单个动作描述模板（Action Card）

每个入选动作都要产出一张「动作卡」，用于下游 8 方向 / 16 帧生成。

```markdown
### 动作编号-名称（如 B1-Light Attack 轻斩）

- **分类**：B. 战斗动作
- **用途**：普通攻击连段第一段
- **时长参考**：0.4s / 约 8–10 帧
- **关键姿势**（3 帧节奏点）：
  1. **起势**：重心后压，剑尖后指，肩部蓄力
  2. **命中**：重心前推，剑水平横扫至体前，手臂完全伸展
  3. **收势**：剑停于身侧，肩部下沉，呼吸复位
- **身体重点**：右肩 → 右肘 → 剑尖的鞭打链
- **武器状态**：右手持剑全程握紧，左手盾保持胸前不动
- **表情**：轻微凝神，眉头微皱
- **循环性**：非循环（一次性播放）
- **8 方向差异要点**：正面 / 背面看到剑横扫扇面；侧面看到剑尖轨迹拉长
- **AI 出图 Prompt**（关键姿势·命中帧）：
  > `<角色三视图锚点>, mid-swing horizontal slash, right arm fully extended, sword parallel to ground at chest height, left arm holding shield close to chest, weight shifted to front foot, focused expression, {美术风格}, {规格}`
```

## 八、动作清单产出格式（Action List Output）

针对一个角色，最终产出一份完整清单：

```markdown
# 【角色名】动作设计清单

## 0. 角色锁定摘要
- 职业 / 性格 / 武器 / 风格 / 用途：……
- 三视图参考：<图链接或占位>

## 1. 动作总览表
| 编号 | 名称 | 分类 | 优先级 | 循环 | 帧数预估 |
|------|------|------|--------|------|----------|
| A1 | Idle 待机 | A | P0 | 是 | 16 |
| A2 | Walk 行走 | A | P0 | 是 | 16 |
| B1 | Light Attack 轻斩 | B | P0 | 否 | 10 |
| ...  | ... | ... | ... | ... | ... |

## 2. 每个动作的动作卡（按第七节模板逐一展开）
### A1-Idle 待机
...
### A2-Walk 行走
...

## 3. 下游对接说明
- 8 方向生成：以每个动作的「关键姿势·命中/中段帧」为基准图，生成 8 个方向变体
- 16 帧生成：以 3 个关键姿势为节奏点，中间补 tween 帧
```

## 九、执行流程（Workflow）

按以下 6 步顺序执行，**每步完成后向用户确认再进入下一步**。

1. **收集输入**：核对第三节 I1–I8，缺失项主动询问用户。
2. **确定预算**：根据 I2/I7 决定动作数量档位（精简 / 标准 / 完整）。
3. **挑选动作清单**：按第四节分类 + 第五节预算，产出「动作总览表」，**先请用户确认清单**。
4. **应用转译规则**：对每个入选动作套用第六节 4 条规则，得到细化描述。
5. **产出动作卡**：按第七节模板，为每个动作生成完整动作卡。
6. **打包交付**：以第八节格式整合，输出最终 Markdown 文档，交给下游 8 方向 Skill。

## 十、检查清单（Checklist）

产出前逐条自检：

- [ ] 所有输入项（I1–I6）已收集，无臆测
- [ ] 动作数量在预算档位范围内，未超支也未遗漏必备类
- [ ] 战斗角色包含 B + C 类，NPC 包含 D 类
- [ ] 每个动作有明确的 3 个关键姿势节奏点
- [ ] 每个动作的**武器状态与手部位置**都被显式描述
- [ ] 每个动作的**性格韵律**（幅度 / 频率 / 重心）已体现
- [ ] 每个动作的 Prompt 尾部包含**美术风格锁**
- [ ] 循环性（loop / one-shot）已标注，供下游 16 帧使用
- [ ] 已标注 8 方向差异要点，供下游 8 方向 Skill 使用
- [ ] 动作总览表已经用户确认后再产出动作卡

## 十一、示例输出（Sample）

**输入**：
- 角色：暗夜刺客「织羽」
- 职业：盗贼 / 性格：冷静敏捷 / 武器：双匕首
- 风格：像素 32×32 / 用途：横版 ARPG / 预算：标准 10 个

**动作总览表**（节选）：

| 编号 | 名称 | 分类 | 优先级 | 循环 | 帧数 |
|------|------|------|--------|------|------|
| A1 | Idle 待机（重心微沉，匕首反握贴身） | A | P0 | 是 | 16 |
| A2 | Walk 潜行步 | A | P0 | 是 | 16 |
| A3 | Run 冲刺 | A | P0 | 是 | 12 |
| B1 | 双匕连刺 | B | P0 | 否 | 10 |
| B2 | 背刺重击 | B | P0 | 否 | 12 |
| B3 | 烟雾闪身（技能） | B | P0 | 否 | 14 |
| B5 | 侧翻闪避 | B | P0 | 否 | 8 |
| C1 | 受击后仰 | C | P0 | 否 | 6 |
| C2 | 倒地消散 | C | P0 | 否 | 16 |
| D1 | 抱臂交谈 | D | P1 | 是 | 16 |

**动作卡示例**（B1）：

```markdown
### B1-双匕连刺
- 分类：B. 战斗动作
- 时长：0.5s / 10 帧
- 关键姿势：
  1. 起势：身体略侧对目标，右匕反握贴腰、左匕正握前指
  2. 命中：左匕前刺至臂展极限，右匕紧随划向咽喉高度
  3. 收势：双匕交叉于胸前，重心回落
- 韵律：冷静敏捷 → 幅度中、频率高、末端干脆无拖尾
- 武器：全程双匕在手，左正握 / 右反握
- 8 方向差异：正/背可见双匕交叉轨迹；侧面强调前刺穿透线
- Prompt（命中帧）：
  > `<织羽三视图>, mid-strike dual dagger stab, left dagger fully extended forward at throat height, right dagger sweeping across chest, body slightly sideways, weight on front foot, calm sharp expression, pixel art 32x32, clean outline, limited palette`
```
